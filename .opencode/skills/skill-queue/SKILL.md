# Skill Queue (คิวงาน)

ไฟล์คิว: `QUEUE.md` ที่รากโปรเจ็ก — ผู้ใช้เพิ่มงานเองได้โดยตรง หรือใช้คำสั่ง `/queue <งาน>`

## รูปแบบรายการ

- `- [ ] งานที่ยังไม่ทำ`
- `- [x] งานที่เสร็จแล้ว` (พร้อมหมายเหตุผลลัพธ์ต่อท้ายบรรทัด)

บรรทัดอื่นที่ไม่ใช่รายการ `- [ ]`/`- [x]` ให้มองเป็นคำอธิบาย ไม่ใช่ตัวงาน

## ขั้นตอนเมื่อถูกสั่งให้ทำงานในคิว

1. อ่าน `QUEUE.md` ทีละบรรทัด หารายการ `- [ ]` (ยังไม่เสร็จ)
2. ทำทีละงานตามลำดับจากบนลงล่าง จนกว่าจะครบทุกงาน หรือจนกว่าจะต้องถามผู้ใช้
3. เมื่องานใดเสร็จ ให้เปลี่ยนเป็น `- [x]` และเพิ่มหมายเหตุผลลัพธ์สั้น ๆ ต่อท้ายบรรทัด เช่น `[x] สร้างฟังก์ชัน login — เสร็จ 16 ส.ค. ตรวจผ่าน`
4. งานที่ทำไม่ได้หรือไม่ชัดเจน ให้ข้ามไว้ ระบุเหตุผล แล้วถามผู้ใช้เมื่อจบรอบ
5. รายงานสรุปเมื่อจบรอบ: ทำไปกี่งาน เหลือกี่งาน อะไรติดขัด

## ระดับอัตโนมัติ (เลือกจาก agent ที่ผู้ใช้กำลังใช้ — กด Tab เพื่อสลับ)

- `auto-guard` (ระดับ 1 ทำตามสั่งเท่านั้น): ห้ามเริ่มคิวเอง — รอคำสั่งจากผู้ใช้เท่านั้น
- `auto-assist` (ระดับ 2 กึ่งอัตโนมัติ): งานในคิวที่ปลอดภัยทำได้เอง งานเสี่ยงต้องถามก่อน
- `auto-drive` (ระดับ 3 เต็มพิกัด): ทำงานในคิวต่อเนื่องเองจนจบ แล้วรายงานสรุป

## ข้อควรระวัง

- ห้ามแตะ `sovereign-os/infra/.env` และห้าม restart runtime / migration (Cold Soak)
- ถ้างานในคิวสั่งให้ทำสิ่งที่ขัดกับกฎเหล็ก ให้ข้ามและแจ้งผู้ใช้ทันที
