release verification

ตรวจว่าไฟล์ที่คุณดาวน์โหลดคือไบต์ที่ผู้พัฒนาลงนามไว้

ทุก release ของ Sovereign OS มาพร้อมเอกสาร sovereign-attest.json ที่เซ็นด้วยกุญแจ Ed25519 ตัวตรวจในหน้านี้ใช้ node:crypto ล้วน จึงตรวจได้โดยไม่ต้องเชื่อ GitHub ไม่ต้องต่อเน็ต และไม่ต้องติดตั้งแพ็กเกจใด ๆ

กุญแจ release (fingerprint)

1afcc7d951d822a7dfe384d89209aed2

ประกาศไว้ที่นี่และในไฟล์ docs/keys/attest-release.pub.pem ของ repository (ตัว fingerprint คือ SHA-256 ของ public key แบบ SPKI, 32 ตัวอักษรแรก) ถ้าค่าที่เห็นไม่ตรงกับที่อื่นที่คุณเชื่อถือ ให้หยุดทันที

1. โหลดสองไฟล์ที่ต้องใช้ตรวจ

  1. sovereign-attest.json จากหน้า Release เดียวกับไฟล์ที่คุณดาวน์โหลด
  2. ตัวตรวจ — สองไฟล์ ไม่มี dependency:
curl -fsSL --create-dirs -o verifier/tools/attest-release.mjs \
  https://raw.githubusercontent.com/krisakornutama/sovereign-origin/main/tools/attest-release.mjs
curl -fsSL --create-dirs -o verifier/tools/attest/document.mjs \
  https://raw.githubusercontent.com/krisakornutama/sovereign-origin/main/tools/attest/document.mjs

2. วางไฟล์ที่ดาวน์โหลดไว้ในโฟลเดอร์เดียว

sov-attest/
  Sovereign-OS-…-portable.exe
  Sovereign-OS-…-win-x64.zip
  sovereign-attest.json

3. รันคำสั่งนี้ (คัดลอกได้เลย)

node verifier/tools/attest-release.mjs --verify sov-attest/sovereign-attest.json \
  --fingerprint=1afcc7d951d822a7dfe384d89209aed2 --dir=sov-attest

ต้องมี Node 20 ขึ้นไป คำสั่งนี้ตรวจสามชั้น: ลายเซ็นของทุก receipt, การต่อ chain ของแต่ละไฟล์ และแฮชของไบต์จริงในโฟลเดอร์ (ขนาดกับ sha256)

อ่านผลลัพธ์อย่างไร

  • ผ่าน — ไฟล์ที่คุณถืออยู่คือไบต์เดียวกับที่เซ็นไว้ และลายเซ็นมาจากกุญแจด้านบน
  • ไม่ผ่าน — อย่าติดตั้ง ให้ลบไฟล์แล้วดาวน์โหลดใหม่จากหน้า Release ถ้ายังไม่ผ่านอีก แปลว่าช่องทางดาวน์โหลดถูกแก้ ให้แจ้งผู้พัฒนา
  • ไฟล์ที่ไม่ถูกเซ็น — ตัวตรวจจะบอกแยก เช่นไฟล์ที่คุณเพิ่มเอง ไม่ทำให้ผลรวมไม่ผ่าน แต่ควรรู้ว่ามันไม่ได้อยู่ในใบรับรอง

อย่าใช้ SHA256SUMS.txt เป็นหลักฐานแทน — ไฟล์นั้นมากับที่เดียวกับไฟล์ติดตั้ง ใครยึดบัญชี distrib ได้ก็แก้ทั้งคู่พร้อมกันได้ fingerprint ข้างบนคือสิ่งที่ต้องมาจากช่องทางอื่น

ถ้าถูกเพิกถอน

ผู้พัฒนาสามารถลงนามเพิกถอนบิลด์ที่พบปัญหาได้ และระบุวันที่มีผลได้ (เพิกถอนเฉพาะของที่ปล่อยก่อนวันนั้น ไม่เหวี่ยงทั้งประวัติ) ตัวตรวจจะปฏิเสธบิลด์ที่ถูกเพิกถอนโดยอัตโนมัติ — อย่าใช้ --allow-revoked เว้นแต่คุณตั้งใจตรวจดูหลักฐานของบิลด์ที่ถูกถอนจริง ๆ

รายละเอียดทั้งหมด (การหมุนกุญแจ การเพิกถอน และข้อจำกัดที่ยังเหลือ) อยู่ใน docs/SOVEREIGN-ATTEST.md
