# โมดูล audit

## เจตนา

_(เจ้าของโมดูลเติม — 1–3 บรรทัด: โมดูลนี้มีอยู่เพื่ออะไร ใครใช้)_

บันทึกการกระทำทั้งระบบ (audit log) สำหรับ SUPERADMIN — ใช้ตอบคำถาม "ใครทำอะไร เมื่อไร" และส่งออกเป็นหลักฐานให้ผู้ตรวจ (PDPA / e-Tax)

- **ส่งออก CSV**: `GET /api/audit/export` ใช้ตัวกรองเดียวกับรายการ (`q`, `actionPrefix`, `from`, `to`) · เพดาน 10,000 แถว · UTF-8 BOM ให้ Excel อ่านภาษาไทย · กัน CSV formula injection (เซลล์ที่ขึ้นต้นด้วย `=` `+` `-` `@` ถูกเติม `'`) · ทุกครั้งที่ดึงออกเขียน `AUDIT_EXPORT` (ใครดึง จำนวนเท่าไร)
  - **ไฟล์ที่ถูกตัดต้องบอกว่าไม่ครบ**: `X-Audit-Export-Rows` / `X-Audit-Export-Total` / `X-Audit-Export-Truncated` (และช่อง `total`/`truncated` ใน `AUDIT_EXPORT`) — คำถามนับต้องใช้ **`where` ก้อนเดียวกับ `findMany`** (สร้างครั้งเดียวแล้วส่งทั้ง `count` และ `findMany`) ไม่ใช่สร้างใหม่หรือนับทั้งตาราง ไม่งั้นตัวเลข "ทั้งหมด" โกหก
  - header ทั้งสามต้องอยู่ใน `exposedHeaders` ของ CORS (`server.ts`) ด้วย มิฉะนั้น browser ซ่อน header ⇒ UI เตือนไม่ได้และไฟล์ที่ขาดจะเงียบสนิท
  - UI ต้องไม่ถือว่า "อ่าน header ไม่ได้" = "ครบ" — ต้องไม่แสดงข้อความยืนยันว่าไฟล์ครบถ้าไม่มีตัวเลข
- **รายการต้องเดินย้อนหลังได้**: `GET /api/audit?limit=&offset=` — `offset` → Prisma `skip` · ดึง `limit + 1` แถวแล้วตัดทิ้งเพื่อรู้ว่ามีหน้าถัดไป (`X-Audit-List-Has-More`) **ห้ามนับทั้งตารางต่อหนึ่งหน้า** เพราะ `audit_logs` โตไม่จำกัด
  - `limit` ติดลบ/ไม่ใช่ตัวเลข = ค่าเริ่มต้น, เพดาน 500 · `offset` ติดลบ = 0 · `offset` เกิน `LIST_MAX_OFFSET` = **400** (ไม่ใช่ลิสต์ว่างที่อ่านว่า "ไม่มีข้อมูลแล้ว")
  - UI ต้องรีเซ็ต `offset` เป็น 0 ทุกครั้งที่เปลี่ยนตัวกรอง/limit/โหมดค้น — ไม่งั้นค้างอยู่หน้าที่ไม่มีข้อมูลแล้วรายงานว่า "ว่าง" ทั้งที่ข้อมูลมี

## ข้อห้าม / ระวัง

_(เจ้าของโมดูลเติม — อะไรที่ห้ามแตะ/ต้องระวังเป็นพิเศษ)_

- **ช่องค้นหา `q` ต้องค้นได้สามที่**: `action_type`, `payload::text` และ **`users.username`** (ILIKE) — ชื่อผู้ใช้ไม่ได้อยู่ใน `payload` เลย จึงต้องกรองที่ relation `user` แยก แล้วเอา **OR** กับผลของ raw search (ไม่ใช่แทนกัน) · ตัวกรองอื่น (`actionPrefix`, `from`/`to`) ยังเป็น AND ตามปกติ
  - เหตุผล: placeholder ของหน้า `/audit` บอกผู้ใช้ว่าค้น `somchai` ได้ — ถ้าถอยกลับไปค้นแค่ action/payload ผู้ตรวจจึงหาคนหนึ่งคนไม่เจอเลยนอกจากเลื่อนดูทั้งตาราง
  - `q` ว่าง = **ห้าม** สร้างเงื่อนไข/ยิง raw query (ไม่สแกนทั้งตารางโดยเปล่าประโยชน์) · ค่าค้นต้องเป็น parameter ของ `Prisma.sql` เสมอ ห้ามต่อสตริง
