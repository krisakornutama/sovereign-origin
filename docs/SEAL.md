# Sovereign Seal — ตราประทับไฟล์ (v1)

เครื่องมือฟรีสำหรับตอบคำถามเดียว: **ไฟล์นี้เป็นไบต์เดียวกันกับตอนที่มันถูกเซ็นหรือไม่ และใครเป็นคนเซ็น**

- เว็บ: `portfolio/seal.html` (ไฟล์เดียวจบ เปิดจาก `file://` ได้ ไม่เรียกเน็ตเลย)
- CLI: `portfolio/seal-cli.mjs` (zero dependency, `node:crypto`)
- หน้าบริจาค: `portfolio/support.html`

## ฟอร์แมตตรา (ตรึงไว้ — ทั้งสองฝั่งต้องผลิตไบต์เดียวกัน)

```
body = {
  "v": 1,
  "alg": "Ed25519" | "ECDSA-P256",
  "at": "<ISO 8601 เวลาที่ผู้เซ็นอ้าง>",
  "items": [ { "name": "<ชื่อไฟล์>", "sha256": "<hex 64>", "size": <ไบต์> } ]
}

canon = JSON.stringify(sortKeysDeep(body))   // เรียงคีย์ทุกชั้น ไม่มีช่องว่าง
sig   = base64(Ed25519_sign(canon))

seal = {
  "body": body,
  "sig": sig,
  "publicKey": { "kty": "OKP", "crv": "Ed25519", "x": "<base64url ของ public key 32 ไบต์>" }
}
```

- `sha256` เป็นแฮชของ **ไบต์จริง** ของไฟล์ ไม่ใช่ของชื่อหรือเวลา
- `fingerprint` ที่แสดงต่อผู้ใช้ = `SHA-256(x)[0..16 ไบต์]` เป็น hex 32 ตัวอักษร (แบบเดียวกับ fingerprint ของ `sovereign-attest`)
- ไม่มี `prev` และไม่มี chain: ตราแต่ละใบเป็นเอกสารเดี่ยว ตรวจได้โดยไม่ต้องมีใบอื่น

## CLI

```bash
node seal-cli.mjs keygen --out seal-key.json          # Ed25519 (ค่าเริ่มต้น)
node seal-cli.mjs keygen --alg p256 --out seal-key.json   # ECDSA P-256
node seal-cli.mjs sign report.pdf --key seal-key.json --out report.seal.json
node seal-cli.mjs verify report.pdf report.seal.json   # exit 0 = ผ่าน, 1 = ไม่ผ่าน
```

ค่าเริ่มต้น: `--key seal-key.json` (สร้างให้ถ้ายังไม่มี), `--out <ชื่อไฟล์แรก>.seal.json`
`sign` รับหลายไฟล์ได้ ตราเดียวเก็บเป็นรายการ

## ขอบเขตความมั่นใจ (อ่านก่อนใช้ตัดสินใจเรื่องสำคัญ)

1. **พิสูจน์ความไม่เปลี่ยน ไม่พิสูจน์ความจริง** — ตราบอกว่าไบต์ไม่ถูกแก้หลังเซ็น และกุญแจใดเซ็น ไม่ได้บอกว่าเนื้อหาถูกต้อง ไม่ได้โกหก หรือมีผลทางกฎหมาย
2. **เวลาเป็นคำอ้าง** — `at` คือเวลาของเครื่องผู้เซ็น ไม่มี timestamp authority ไม่มี witness
3. **ตัวตนต้อง pin เอง** — `publicKey` เดินทางมากับตรา ใครสร้างกุญแจใหม่ก็เซ็นได้ การจะเชื่อว่า "ก. เซ็น" ต้องเทียบ fingerprint กับช่องทางที่รู้จักอยู่แล้ว (หน้าเว็บหลัก อีเมลที่ลงนาม ฯลฯ)
4. **กุญแจอยู่ในเบราว์เซอร์** — `localStorage` ของโดเมนนั้น (หรือของ `file://`) ล้างข้อมูลหรือเปลี่ยนเครื่องแล้วต้องนำเข้าจากไฟล์สำรอง กุญแจส่วนตัวถูกเก็บเป็น JSON ธรรมดา: ใครเข้าถึงโปรไฟล์เบราว์เซอร์ได้ก็ใช้กุญแจได้
5. **อัลกอริทึมขึ้นกับเบราว์เซอร์** — เครื่องที่ WebCrypto ไม่มี Ed25519 จะเซ็นด้วย P-256; ตราบอก `alg` ไว้เสมอ ผู้ตรวจไม่ต้องรู้อะไรล่วงหน้า
6. **ไฟล์ใหญ่** — ฝั่งเว็บโหลดไฟล์เข้าหน่วยความจำทั้งก้อนก่อนแฮช (ไม่มี streaming digest ใน WebCrypto) ฝั่ง CLI แฮชแบบ stream จึงใช้กับไฟล์หลาย GB ได้
7. **ไม่มีตัวตนของผู้ออก / ไม่มี revocation** — ไม่มีการเพิกถอนตรา ถ้ากุญแจหลุด ต้องประกาศ fingerprint ใหม่และบอกผู้ใช้เอง

## สิ่งที่ไม่ทำโดยตั้งใจ

- ไม่มีเซิร์ฟเวอร์ ไม่มีบัญชี ไม่มี telemetry ไม่มี analytics — จึงไม่มีตัวนับจำนวนผู้ใช้ (วัดได้แค่ยอดดาวน์โหลดถ้าแจกเป็น release asset)
- ไม่ได้อ้างมาตรฐาน C2PA หรือ EU AI Act: ฟอร์แมตนี้เป็นของเราเอง เรียบง่ายและตรวจได้ด้วยโค้ด 50 บรรทัด

## ความเข้ากันได้ของไบต์ระหว่างสองฝั่ง

ทั้งสองฝั่งใช้ `JSON.stringify` ของออบเจ็กต์ที่เรียงคีย์แล้ว (คีย์เป็น ASCII ทั้งหมด) จึงได้สตริงเดียวกันทุกแพลตฟอร์ม
ตราที่เซ็นในเบราว์เซอร์ต้อง `verify` ผ่าน CLI และกลับกัน — เทสต์อยู่ในขั้นตอนตรวจก่อนปล่อย (keygen → sign → verify, แล้วแก้ 1 ไบต์ต้องได้ exit 1)
